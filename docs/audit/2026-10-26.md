# Project audit, 2026-10-26

Five parallel reviews checked the code against the build spec, ran probes and wrote reproduction tests: CLI/install/update, pipeline, enforcement/gates, packaging, and acceptance/docs. The headline findings were then re-verified by hand: the npm registry entry, 14 shell-policy probes and 3 case-variant edits, and a reading of the cited code. The test suite passes (315 pass, 4 skipped), so everything below is a gap that the tests don't cover.

IDs: **S** safety/enforcement, **P** pipeline correctness, **D** distribution, **G** spec gaps, **T** missing tests, **C** docs. Severity: high / medium / low.

## S — Agents can get around enforcement (fix first)

The "never push" and edit-scope guarantees currently rest mostly on the shell parser. These all get through it:

**Direction:** the parser can't win this alone. The proposal is a hardening slice covering:
- allowlisting env assignments and `-c` keys, and blocking exec-capable git options;
- parsing keywords, `cd`, xargs and exec;
- resolving real paths and matching case-insensitively;
- running gates and installs with `agentGitEnv` and a curated env;
- stripping secrets from agent shell envs;
- auditing against the merge base, and blocking `git commit` for agents;
- keeping run state and session context out of agent reach, by hashing them or holding them in memory;
- adding a real OS sandbox for agent shells where one exists (`sandbox-exec` on macOS, bwrap on Linux).
