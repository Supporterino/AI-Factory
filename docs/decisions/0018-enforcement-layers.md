# ADR-0018: Enforcement layers (plugin, CLI, git)

**Context.** §8 asks for the opencode plugin where hooks exist and CLI enforcement for anything the plugin cannot guarantee. The V2 plugin API is young (gap G1), and opencode cannot resolve npm packages from `.opencode/plugins/`.

**Decision.**
- **Plugin.**
  - `src/plugin/entry.ts` is bundled (`bun run build:plugin`) into one dependency-free ES module (~50 KB, Node built-ins only), committed as `templates/plugin/factory-plugin.txt`. A test fails if it is stale.
  - `init` renders it as `.opencode/plugins/factory.js`.
  - It is active only when the opencode server runs with `AI_FACTORY_WORKSPACE` (set by the CLI), and only for factory agents. A factory agent without a session context file (`.factory/sessions/<session>.json`) is refused every tool call.
- **Shared policy code.** The plugin and the CLI judge with the same pure modules: `policy/shell.ts`, `policy/scope.ts`, `policy/paths.ts`, `approval/approval.ts`. Those modules avoid zod to keep the bundle small.
- **Shell blocklist** works on a parsed command (`policy/shell-parse.ts`) after unwrapping:
  - `env`, `command`, `exec`, `nohup`, `time`, `nice`, `timeout`, `xargs`, `watch`, `flock -c`, `find -exec`, `sh|bash|zsh -c`, `eval`;
  - aliases defined in the command, functions (bodies are checked), subshells, `$(…)`, backticks, `<(…)`;
  - here-docs and literal `echo`/`printf` piped into a shell; generated input piped into a shell is blocked;
  - scripts executed by path (shell scripts are parsed; other interpreters get a text scan); a script written and executed in the same command is blocked.

  Command names generated at run time (`$CMD`, `$(…)`) are blocked. git subcommands not on a known list are blocked, so git aliases cannot hide a push. Unparseable commands are blocked.
- **Secret files.** `.env*` except `.env.example/.sample/.template/.dist/.defaults`; keys (`*.pem`, `*.key`, `id_rsa`…); kubeconfigs; cloud and registry credentials. They are blocked as arguments and redirect targets in shell, and for read/edit tools.
- **Embedded languages** (`python -c`, `node -e`, interpreter scripts) only get a text heuristic. Layers 2 and 3 below are the real backstop for pushes from code we cannot parse.

| Rule                                                                                   | Plugin (`execute.before`)                                                  | opencode permissions (agent frontmatter) | CLI                                                                                   | git                                                    |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| No `git push`                                                                          | parsed blocklist                                                           | `git push*` deny                         | agent env `pushInsteadOf` → every push fails                                          | `pre-push` hook rejects when `AI_FACTORY_AGENT` is set |
| Other blocked shell (force, rewrite, remote, config writes, sudo, curl\|sh, env dumps) | parsed blocklist                                                           | coarse `SHELL_DENY` patterns             | —                                                                                     | —                                                      |
| Edit scope per role                                                                    | `checkEdit` (role, touches, test globs, architect dirs)                    | `edit` allow/deny per role               | post-session `auditChanges` on the worktree diff; violations are reverted and counted | —                                                      |
| Factory files never edited                                                             | protected paths                                                            | protected-path denies                    | audit + `init`/`update` hash checks                                                   | —                                                      |
| No implementation edits before approval                                                | approval hash check (fs)                                                   | —                                        | dispatch only after hash **and** spec-commit check                                    | —                                                      |
| Writes outside the worktree                                                            | path resolution (edits, redirects, cp/mv/tee/sed -i…)                      | `external_directory` deny                | audit of the AI repo status after each session                                        | —                                                      |
| Secret files                                                                           | read/edit/shell checks                                                     | read/edit denies                         | log redaction                                                                         | —                                                      |
| Graph updates only by the CLI                                                          | `graphify update/extract/hook/install` blocked                             | coarse denies                            | serialised updates                                                                    | —                                                      |
| Task state only by the CLI                                                             | `.factory/**` protected                                                    | `.factory/*` deny                        | run state written only by the CLI, under a lock                                       | —                                                      |
| Retry budget                                                                           | —                                                                          | —                                        | scheduler (ADR-0017)                                                                  | —                                                      |
| Logs                                                                                   | every call logged (`tool`, `blocked`, `waste`, `tool-result`) and redacted | —                                        | gate results logged; pruned after `logs.retentionDays`                                | —                                                      |

**Consequences.** Every rule has at least two independent layers, except the retry budget, which only the CLI can count. If the plugin fails to load, opencode's own permission rules, the post-session audit and the git layers still hold. `doctor` (slice 13) checks that the plugin file matches the lock hash.
