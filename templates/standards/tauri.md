## Summary

- Rust lives in `src-tauri/`: code in `src/lib.rs` and its modules; `src/main.rs` only calls `run()`.
- Commands take serde arguments (camelCase keys in JS) and return `Result<T, E>` where `E` implements `Serialize`.
- Slow commands are `async`; async commands with borrowed arguments such as `State<'_, T>` must return `Result`.
- Use commands for request/response, channels for ordered or large streams, events only for small notifications.
- Grant least privilege: narrow permissions with scopes, per window label, in `src-tauri/capabilities/`; commands still validate their own input.
- Keep `app.security.csp` strict; never use `dangerous…` options to make something work.
- Test command logic in Rust; test the frontend with `mockIPC` from `@tauri-apps/api/mocks` and `clearMocks()` after each test.

## Structure

<!-- [structure]; [config]; [capabilities] Schema Files; [permissions]; [plugin-fs] Setup -->
- Keep the repo's existing layout and module conventions. <!-- factory -->
- Put Rust code in `src/lib.rs` and its modules; `run()` carries `#[cfg_attr(mobile, tauri::mobile_entry_point)]`. Leave `src/main.rs` as the call to `run()`.
- Capabilities are JSON or TOML in `src-tauri/capabilities/`; app permission files are TOML in `src-tauri/permissions/`. `gen/schemas` is generated by `tauri-build`: reference it from `$schema`, never edit it.
- Platform files (`tauri.linux.conf.json`, …) merge as JSON Merge Patch: arrays such as `app.windows` are replaced whole, so repeat every entry you keep.
- Add plugins with `tauri add <plugin>` (crate, npm package and default permission together) and register them with `.plugin(…::init())`. Keep `tauri`/`tauri-build` on the CLI's minor version; commit both lockfiles.

## Commands

<!-- [calling-rust] Basic Example, Passing Arguments, Returning Data, Error Handling, Async Commands, Accessing an AppHandle, Invoking Multiple Commands -->
- Commands in a module are `pub`; commands directly in `lib.rs` must not be `pub`. Names are global: keep them unique across modules, and register all in one `generate_handler![…]` (a second `.invoke_handler` replaces the first).
- Rust snake_case parameters arrive as camelCase JS keys: `fn save_note(note_id: u32)` is called as `invoke("save_note", { noteId })`.
- Arguments implement `Deserialize`, return values `Serialize`. Return `tauri::ipc::Response` for large binary data instead of JSON-encoding it.
- Return `Result<T, E>`; `Err` rejects the JS promise. `E` must implement `Serialize`, so give a `thiserror` enum a manual impl (use a `tag = "kind"` form when the UI branches on the error):

```rust
impl serde::Serialize for Error {
    fn serialize<S: serde::Serializer>(&self, s: S) -> Result<S::Ok, S::Error> {
        s.serialize_str(&self.to_string())
    }
}
```

- Non-`async` commands run on the main thread and freeze the UI. Make I/O and heavy work `async fn` (or `#[tauri::command(async)]`).
- An async command with a borrowed parameter must return `Result`: take `String` rather than `&str`, and return `Result` whenever `State<'_, T>` is a parameter.
- Commands taking `AppHandle<R>`/`WebviewWindow<R>` that must run under the mock runtime are generic over `R: tauri::Runtime`.
- Call commands through one typed frontend module per domain, not `invoke("…")` strings in components. <!-- factory -->

## State

<!-- [state] -->
- Register with `app.manage(…)`; read with `State<'_, T>` in commands or `app_handle.state::<T>()` elsewhere. Tauri wraps state in `Arc` already: manage `Mutex<T>`, not `Arc<Mutex<T>>`, and move a cloned `AppHandle` into threads.
- Use `std::sync::Mutex` by default; use the async runtime's `Mutex` only when the guard is held across `.await` (e.g. a DB connection).
- An unmanaged or mistyped `State<'_, T>` fails at runtime, not compile time. Define `type AppState = Mutex<AppStateInner>;` and use the alias everywhere.

## Events and channels

<!-- [calling-frontend] Event System, Channels; [calling-rust] Event System, Channels -->
- Use events (`emit`, `emit_to`, `emit_filter`) for small notifications. Payloads are JSON strings: `Serialize + Clone`, `rename_all = "camelCase"`.
- Use a `tauri::ipc::Channel<T>` command argument for progress, streams or large data; the frontend passes `new Channel<T>()` from `@tauri-apps/api/core`.
- Capabilities do not cover events, and global events reach every listener; send window-private data with `emit_to` (which global `listen` does not receive) or a channel.
- `listen` resolves to an unlisten function: await it, and unlisten on unmount:

```ts
useEffect(() => {
  const un = listen<Progress>("download-progress", (e) => setProgress(e.payload));
  return () => {
    un.then((f) => f());
  };
}, []);
```

## Capabilities and permissions

<!-- [security]; [capabilities]; [permissions]; [scope]; [app-manifest]; [plugin-fs] Permissions -->
- One capability file per purpose: `identifier`, `description`, `windows` (labels), `permissions`; `platforms` and `remote.urls` only when needed.
- Once `app.security.capabilities` lists identifiers, unlisted capability files are ignored; add new ones to that list. Labels, not titles, are the boundary; a window in several capabilities gets their union. Avoid `"windows": ["*"]`; give window creation only to privileged windows.
- Prefer single-command permissions (`core:window:allow-set-title`, `fs:allow-read-text-file`) over broad sets. Scoped plugins such as `fs` reject paths no scope allows; `deny` beats `allow`:

```json
{ "identifier": "fs:allow-read-text-file", "allow": [{ "path": "$APPDATA/notes/**" }] }
```

- App commands are callable from every window by default. To gate them, list them with `tauri_build::AppManifest::new().commands(&[…])` in `build.rs` and grant the generated `allow-<command>` permission per capability.
- Use `remote.urls` only for origins you own (on Linux and Android an iframe is indistinguishable from its window). Capabilities do not make command code safe: each command enforces its scope and validates the paths, URLs and ids it receives.

## CSP and config security

<!-- [csp]; [config-ref] SecurityConfig, withGlobalTauri; [updater] Signing updates -->
- Set `app.security.csp` (and `devCsp` if dev differs) as tight as possible; Tauri adds hashes and nonces for bundled assets at compile time.
- No scripts from CDNs or hosts you don't own; add `'wasm-unsafe-eval'` to `script-src` only for Rust/WASM frontends.
- Never set `dangerousDisableAssetCspModification`. Leave `app.withGlobalTauri` false and import from `@tauri-apps/api`. Keep `assetProtocol` off unless needed, then narrowly scoped.
- Only the updater public key goes in `tauri.conf.json`; the private signing key never enters the repo.

## Testing

<!-- [tauri-test]; [mocking]; [calling-rust] Accessing an AppHandle -->
- The tester edits only test files: Rust in sibling `tests.rs` modules and `tests/`, frontend in `*.test.ts(x)`. <!-- factory -->
- Every spec scenario maps to at least one test named after it, including each command's error result. Add WebDriver end-to-end tests only where the repo already has them. <!-- factory -->
- Test command logic as plain functions. For IPC-level tests use `tauri::test` (`mock_builder`, `mock_app`, `get_ipc_response`, `assert_ipc_response`): unstable, behind the `tauri` crate's `test` feature.
- When IPC tests are planned, the implementer enables that feature (e.g. under `[dev-dependencies]`); the tester cannot edit `Cargo.toml`. <!-- factory -->
- Frontend: `mockIPC((cmd, args) => …)`, `clearMocks()` in `afterEach`, a `window.crypto` polyfill under jsdom. `mockWindows` fakes labels only; `shouldMockEvents: true` fakes `emit`/`listen`, not `emitTo`.

## Gates in this factory

<!-- factory -->
- Gates run in `src-tauri/`: `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo check --all-targets`, `cargo test --workspace` (affected crates when scoped).
- `cargo check` compiles `tauri.conf.json` and the capabilities in, so an unknown permission or broken config fails it; capability-only changes re-run the gates.
- `generate_context!` needs `build.frontendDist` to exist; before compiling, a missing local dir is created empty (read from `tauri.conf.json` only).
- Frontend gates come from its TypeScript/React profile. On Linux the cargo gates need WebKitGTK and Tauri's other system packages.
